# 安卓版 v2.0 预览版拆包与借鉴报告

> 调查对象：`MewX/light-novel-library_Wenku8_Android` 的 pre-release `v2.0.4 Testing`（2026-11-21）
> 对照版本：公开版 `v1.30`（2026-08-29）
> iOS 对照版本：本项目 `1.4.0 (134)`

---

## 一、这个预览版是什么

`v2.0.0` 起安卓端做了一次**完全重写**：

| 项目 | v1.30 | v2.0.4 |
| --- | --- | --- |
| UI 框架 | Java + XML 布局 | Kotlin + Jetpack Compose（M3 Expressive） |
| 包名 | `org.mewx.wenku8`（v1 命名空间） | `org.mewx.wenku8`（v1 移至 `...wenku8.v1`） |
| APK 体积 | 10 MB | 6.5 MB |
| 数据源 | 中转 + 网页 | **仅中转**（`enforce relay-only IP routing`） |
| 中转域名 | `wenku8-relay.mewx.org` | `mewx-android.wenku8.app` |
| 传输 | 明文表单 | **WK8-RNE-1 密封传输** + 426 强制升级流程 |
| 分发 | Play Store | Play（AAB）+ 直接分发（APK）+ 应用内更新 |

Release note 只有一句「全新的 2.0 版本！！！」，更新内容需要从提交历史与拆包结果还原。

## 四、值得借鉴的部分

按「价值 / 成本」排序，并结合 iOS 现状给出判断。

### 1. 书内搜索（高价值，中等成本）

安卓能在**当前章节即时检索**，并能「跨全书所有已离线缓存章节秒级定位原句」。

iOS 现在只有书名搜索。正文其实都在本地（离线章节）与解析后的块结构里，做全文检索不需要网络：

- 在 `ReaderView` 加入搜索面板，遍历当前章节的 `[Block]` 做高亮定位
- 扩展到已下载章节：遍历离线存储的正文文件
- 搜索结果点击后跳到对应章节的对应位置

这是本报告里**性价比最高**的一项。

### 2. 书签 + 摘录（高价值，低成本）

安卓支持书签和「书签摘录」，并在工具栏提示如何记录锚点。

iOS 的阅读进度是按章节存的，没有页级锚点。可以：

- 在 `ReaderPreferences` 或独立存储里按 `(aid, cid, 页码/偏移)` 存书签
- 书签列表里显示所在章节与摘录的第一行
- 与现有的进度恢复逻辑共用定位代码

### 3. TTS 朗读（中等价值，低成本）

iOS 有系统 `AVSpeechSynthesizer`，接进阅读器即可「从当前页朗读」，配合现有的翻页逻辑自动续读。

注意点：中文语音需要选对 `zh-CN` 音色；后台播放要配 `AVAudioSession`；朗读与翻页的边界需要处理（当前 iOS 无翻页动画，反而简单）。

### 4. 阅读统计（中等价值，中等成本）

安卓有「周阅读活跃热力图 / 活跃天数 / 累计时长 / 累计字数」。

iOS 可以在阅读器里按分钟累计、按天落盘（`UserDefaults` 或本地 JSON），设置页加一个统计卡片。数据量很小，不需要服务端。

### 5. 纸张背景与自定义字体（中等价值，中等成本）

安卓的「排版与纸张工作室」是目前观感差距最明显的地方：羊皮纸、护眼绿、纯黑 AMOLED、自定义日间背景图、TTF/OTF 导入。

iOS 已有主题与封面取色，可以分两步：

- 先做**纸张底色**（纯色 + 噪点纹理，代码生成即可，无需资源文件）
- 再做**字体导入**（`UIAppFonts` 动态注册 + `CTFontManagerRegisterFontsForURL`）

### 6. 插图画集（中等价值，低成本）

iOS 已经在正文里渲染插图了，缺的是：

- 图片点击放大（`fullScreenCover` + 缩放）
- 按书收集所有插图（从已解析章节里抽 `img`）

### 7. 应用内更新检查（中等价值，低成本）

我们靠 GitHub Releases 分发，可以：

- 启动时请求 `releases/latest`，比较 `CFBundleShortVersionString`
- 有新版本时在设置页显示徽标 + 弹一次提示，点击跳转 GitHub 页面

不需要自动下载安装（iOS 侧无法像安卓那样直接装 APK）。

### 8. 公告与签到（低价值，低成本）

安卓的公告卡与每日签到属于「锦上添花」。签到能拿积分，但我们的 App 不做账号体系外的事情，价值有限。

### 9. 网络诊断（低价值，成本高）

安卓那套是为了解决中转域名被墙：DoH TXT 拉优选 IP、纯 IP 路由、密封传输。我们的中转只有固定域名，且没有自建能力，**不建议照搬**。

## 五、不建议照搬的部分

| 项目 | 原因 |
| --- | --- |
| 3D 书脊书架 | 大量自定义绘制与物理逻辑，收益偏观感，维护成本高 |
| 五种翻页引擎 | iOS 端当前无动画反而更稳，引入卷曲动画与手势冲突风险大 |
| 竖排 / 右起 | 中文轻小说读者需求很小，实现成本高（排版引擎重写） |
| 墨水屏模式 | 面向特定设备，iOS 用户群几乎不涉及 |
| 密封传输 WK8-RNE-1 | 需要中转侧配套，我们没有实现能力 |
| 广告 | 与项目定位不符 |
| Play 双通道更新 | 依赖 Google Play，iOS 无对应机制 |

---

## 六、需要留意的风险

1. **中转协议可能升级**。安卓端已经切到 `WK8-RNE-1` 密封传输与新域名，如果公共中转日后只接受密封请求，我们现有的明文表单会失效。建议在 `RelayClient` 里保留一个「协议版本」开关，便于快速适配。
2. **安卓端已放弃网页模式**，说明官方对网页端的态度在收缩。我们的混合模式是有价值的差异化能力，应继续维护。
3. **标签体系是 iOS 端独有的**（安卓 v2 无标签），这是当前的领先项，值得在 README 里突出。

---

## 七、结论

- 安卓 v2 是**重写 + 阅读器体验升级**，方向是「把阅读器做成专业阅读软件」。
- 对 iOS 最有价值的三个借鉴点是：**书内搜索**、**书签摘录**、**TTS 朗读**——都不依赖服务端，成本可控。
- 观感层面值得跟进的是**纸张背景**与**自定义字体**。
- 不建议跟进 3D 书架、翻页动画、竖排、墨水屏这类高成本低收益项。
- 数据源方面，我们比安卓多出**网页模式、混合模式、标签体系、热度排名**，这些是优势项。
